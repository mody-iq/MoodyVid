## Fixed this session (branch `main`, commits d964689 + c662d2f)

### Ad blocker never blocked anything (real, root-caused)
`MVAdBlocker` built one big rule with `if-domain: [<48 ad hosts>]` and
`url-filter: ".*"`. Reading WebKit's parser
(`Source/WebCore/contentextensions/ContentExtensionParser.cpp`) confirms
`if-domain` is parsed into `ActionCondition::IfTopURL` — it matches the
**top-level page** URL, not the request. So the list only fired when the page
itself was on an ad host, i.e. never for a normal page loading ads. That is why
blocking looked dead even after the earlier "retry with a fallback list" fix.

Fix: generate one `url-filter` per host that matches the request URL —
`^https?://([a-z0-9-]+\.)*<escaped host>(:[0-9]+)?/` — joined with `|` in
chunks of 8. Verified the generated regexes against real ad URLs offline.

Also: when WebKit refuses the whole list it now recompiles **each rule alone**
and keeps the accepted ones (`probeRules:` → `MoodyVidAdsGood`). One bad rule
can no longer disable all of them. Rules are now built with
`NSJSONSerialization` from an array of single-rule strings (`MVAdBlockRules()`),
not a hand-escaped `@"...\n"` literal, so the JSON can't drift.

### Pause/resume kept throwing away the video fragment
The 1080p+ path downloads a `.video` fragment, then an `.audio` one, then muxes.
A pause during the audio step ran `discardTrackedFragmentsFor:`, deleting the
finished video fragment — so "Resume" re-downloaded the whole video. Now the
fragment is kept when the error is `"paused"`, and `startMergedJob:` looks for
an `existingFragmentFor:marker:@".video"` and reuses it.

### finishJob could clobber a resumed job
A pause unwinds asynchronously. If the user resumes before the paused call
returns, `resumeDownload:` has already queued a new job under the same
identifier; the late `finishJob:` then removed it from `_running` and rewrote
the record. Guard: `if (_running[id] && _running[id] != job) return;`.

### Traps that actually cost a build
- **`nullable` inside `NS_ASSUME_NONNULL`.** Writing `@property (copy, nullable)
  NSString *x;` in a header that opened `NS_ASSUME_NONNULL_BEGIN` is a hard
  error. Use `_Nullable` (or `nullable` after the type) instead.
- **A bare message-send inside a literal.** `@[[self foo], @2]` where `[self foo]`
  has no declared type does not parse. Assign to a local first.
- **`UTTypePlainText` and friends are weak globals.** They compile but the link
  fails with an undefined symbol until `-framework UniformTypeIdentifiers` is
  added to `scripts/build.sh`. Do the same for any new system framework.
- **`copy` block properties and cell reuse.** `MVTaskCardCell`'s `onAction` must
  be cleared in `-prepareForReuse`, and the explicit `setOnAction:`/`setOnSelect:`
  in the .m is deliberate — a synthesised setter there was being bypassed.

## LAME/MP3 was dead code (found by auditing "is anything unfinished?")

`scripts/build.sh` passed `-I "$LAME_DIR"`, but `tar --strip-components=1` leaves the
header at `$LAME_DIR/include/lame.h`. So `#if __has_include(<lame.h>)` in
`MVMediaConverter.m` was ALWAYS false, `MV_HAS_LAME` was 0, and the whole MP3
encoder was never compiled. Two consequences:
* choosing "MP3 (audio)" logged "MP3 encoding is not available on this build" and
  silently saved the original `.m4a`, while the row reported success (the engine's
  failure branch relabels the file with its real extension);
* the build linked `libmp3lame.a` for nothing.

Fixing the include path (`-I "$LAME_DIR/include"`) then made CI fail, which is the
real lesson: **code behind `__has_include` can rot for months because it is never
type-checked**. The repaired path had:
* `CMFormatDescriptionGetAudioStreamBasicDescription` — does not exist; the audio
  accessor is `CMAudioFormatDescriptionGetStreamBasicDescription` (returns a
  pointer, may be NULL).
* a `goto` that jumped over a stack-array initialisation → hard error. Replaced
  the goto cleanup with a single tail guarded by nullable handles.
* an mp3 output buffer sized from the *sample* count while LAME was handed a
  *frame* count, and the frame count was uncapped → heap overrun on a big sample
  buffer. Now encodes in slices of at most `kMaxFrames` (8192), buffer sized from
  that exact cap, and the helper takes the capacity.
* trailing bytes that were not a whole frame were dropped → carried over now.
* a half-read track reported success → only `AVAssetReaderStatusCompleted` is a
  complete file; otherwise fail and `remove()` the partial output.

Validation trick worth reusing: LAME builds for the HOST in ~1 min
(`./configure --disable-shared --enable-static --disable-frontend --disable-decoder
--disable-asm && make`), so the slicing logic can be exercised for real with a
generated sine wave instead of only reasoning about it. Confirmed stereo+mono
encode without overrunning the buffer, all input consumed, output has frame sync
words.

## Files tab: kind filter + reveal-from-downloads, and the flat surface pass

- **Kind filter is tree-wide, All is per-folder.** `MVFileKind` (All/Video/Audio/
  Other) + `MVExtensionIsVideo`/`MVExtensionIsAudio`. Video/Audio/Other walk the
  whole library by extension so a file is found wherever it sits; All keeps the
  old folder browsing. Consequence: the sort and new-folder bar buttons are
  meaningless in a kind filter, so `refresh` disables them (`item.enabled`).
- **`visibleEntries` returns absolute paths, not names.** Every row call site
  (`cellForRow`, `didSelect`, trailing swipe, long-press, context menu, the
  playable-queue builder) now reads `[self visibleEntries][indexPath.row]` and
  takes `path.lastPathComponent` for the display name. Mixing the two shapes
  (name + `stringByAppendingPathComponent`) was the old pattern and silently
  breaks under a kind filter.
- **Memoise `visibleEntries`.** The table asks once per row; a kind filter walks
  the whole tree, so without the `rowCache`/`rowCacheKey` (key =
  kind|filter|currentDirectory) the Files tab would do N full tree walks.
  `refresh` always clears the cache, because files land on disk behind the
  app's back and the key alone can't see that.
- **Kind change inside a subfolder must pop to root AND forward the choice.**
  The root is a different `MVFilesViewController` instance, so `kindChanged:`
  copies `filterKind` onto `navigationController.viewControllers.firstObject`
  before popping. Popping without that leaves the root on All.
- **Reveal flow.** `MVDetailsSheet.onRevealInFiles` → notification →
  `MVTabBarController.revealFile:` (selectedIndex = 2, popToRoot, `revealPath:`).
  `revealPath:` bails to `revealTarget` when `!isViewLoaded || view.window == nil`
  (a tab switch pushes the VC but does not attach its window in the same turn),
  so `viewWillAppear` does the scroll. Scroll then flash must be split across a
  `dispatch_async(main)` — the cell is not dequeued until the scroll lands.
- **`UIScrollView` + Auto Layout trap (Home platform shelf).** Pinning the
  content stack to the scroll view's *frame* anchors ties content width to the
  visible width, so it can never scroll and fixed-width children fight the
  constraint. Pin to `scroll.contentLayoutGuide` and give the height from
  `scroll.frameLayoutGuide`. Also set the horizontal stack's `alignment` to
  Center — the default Fill stretches a fixed-height tile.
- **Flat surface pass.** `applyCardStyle:` is now a solid fill (blur, border and
  shadow removed; `kGlassBlurTag` deleted). Same for the player mini bar, the
  parked card, the FAB, the sniffer button and the contact sheet backdrop. Nav
  and tab bars are opaque + hairline; `prefersLargeTitles = NO` everywhere;
  the inline title font is set once in `MVTabBarController` rather than three
  times in view controllers. The shell wallpaper is gone. Rationale: a long
  list should not pay a compositing pass per row, and blur behind an opaque
  card was invisible work.
