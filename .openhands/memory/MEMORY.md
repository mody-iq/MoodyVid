# MoodyVid memory index
- Build: GitHub Actions; push to main triggers IPA build (`gh run list` to watch). `Sources/*.m` glob picks new files.
- Push needs tokenized remote (GITHUB_TOKEN) — remote gets set with resolved token.
- Player: MVPlayerCenter singleton owns the AVPlayer; floating mini-bar; audio bg mode declared. Full player is a CUSTOM MVFullPlayerViewController (AVPlayerLayer + glass bar), NOT AVKit — AVPlayerViewController pauses its player on dismissal (the "audio stops on shrink" bug). Never transfer the player to another VC; hideFloatingBar/showFloatingBar control the mini bar.
- Files tab plays videos IN a glass card (in-tab), not a modal. AVPlayerLayer shared-player card, 16:9 surface.
- Wallpapers: 10 keys, gradient or raster pattern (`MVTheme.wallpaperUsesImage:`). `CAGradientLayer.colors` takes CGColorRefs — resolve dynamic colors, re-apply via `refreshWallpaperIfPattern:` on trait change. Shell wallpaper is NO LONGER used (removed 2026-11-11); per-tab wallpapers remain via `applyWallpaperTo:` on each VC's own view. The old "wallpaper only in the middle" trap is historical: it was caused by a nav controller's opaque view masking the shell wallpaper.
- Surfaces are FLAT (2026-11-11, supersedes the earlier glass look): `applyCardStyle:` is a plain solid fill — no blur, no border, no shadow. The old `kGlassBlurTag` blur view is gone, `glassCard` returns an opaque `card`, and the per-VC floating bars (player mini bar, parked card, FAB, sniffer button) had their `UIVisualEffectView` + shadow removed. Nav/tab bars use `configureWithOpaqueBackground` + a hairline `shadowColor`, `prefersLargeTitles = NO`, titles semibold 17. The shell no longer paints a wallpaper (`MVTabBarController.view` is `[MVTheme background]`); each tab paints its own. Trait changes still call `applyTheme`.
- Settings: Appearance/Wallpaper rows present action sheets (Language pattern); swatches via `wallpaperSwatchViewForName:`.
- Home brand = `MVGradientLabel` (kCGTextClip gradient text) + glassy badge.
- Python: MVPython startOnQueue imports `downloader` (yt-dlp) at launch so first download doesn't stall.
- Traps: `.CGColor` after `?:` mis-binds → resolve colors into locals first. Big heredoc writes truncate; use file_editor/python.
- Browser (rebuilt 2026-11-09): multi-tab (MVBrowserTab, max 8), home page (MVBrowserHome: shortcuts/bookmarks/history), tab grid (MVTabsViewController), sniffer (MVSnifferScript injected at documentStart + MVSnifferStore per tab + MVMediaProbe HEAD/Range with cookies+referer), ad blocker (MVAdBlocker WKContentRuleList), found-media sheet (MVSnifferSheet). Popups without a user gesture are dropped; magnet links route to the manager.
- Download stack: MVDownloadTask/MVTaskStore (JSON in App Support, atomic, corruption-tolerant), MVDownloadManager (queue: maxConcurrentTasks, maxConnections, speedLimit, wifiOnly), MVFastDownloader (multi-connection segmented: ranged probe → up to `connections` .partN segments in parallel → streamed join off-main; single-connection fallback when the server ignores Range; Range resume + ETag guard + throttle). MVHLSDownloader (m3u8: master→variant, AES-128 CBC, EXT-X-MAP fMP4, MPEG-TS→MP4 remux via AVFoundation; live/SAMPLE-AES fail with a localized reason). MVMPDDownloader (mpd via NSXMLParser: best video rep, SegmentTemplate $Number$/$Time$ + SegmentTimeline, SegmentList, SegmentBase + BaseURL chain; 4-way parallel segment fetch; live/ContentProtection fail with a localized reason). Torrent engine BUILT (Foundation-only core in Sources/MVTorrent*.m + MVBencode/MVSHA1/MVMagnet; peer wire, storage, tracker announce). Magnets resolve via BEP 9 metadata exchange (2026-11-11): the job starts from a placeholder metadata + the magnet's trackers, announces, parses each peer's BEP 10 extended handshake for its per-peer `ut_metadata` id, requests 16 KiB metadata pieces, verifies the assembled info dict against the magnet's info-hash, then re-wraps it as a one-key .torrent and hands it to the normal parser. TRAP: that wrap must append the RAW info-dict bytes (`d4:info` + bytes + `e`) — bencoding `@{@"info": bytes}` encodes the dict as a bencoded STRING (length-prefixed), so the parser slices the wrong bytes and the info-hash never matches. Helper: `+[MVBencode torrentDataWithInfoDict:]`. Peers found during resolution were built when pieceCount was still unknown, so `prepareJob` drops + reconnects them from the addresses it holds. `scripts/torrent-tests.sh` (macOS-only, system clang) is the gate; it runs in CI before the IPA build. The two stream engines share `enqueueStreamItem:source:label:` in the manager.
- Downloads tab shows BOTH engines in one list via `MVDownloadRow` (wraps MVDownloadRecord and MVDownloadTask). Adding a new row kind = extend MVDownloadRow + cellForRow.
- UI redesign (2026-11-11, stage 1+2): one card language across Home/Downloads/Files/More. Shared components: `MVTaskCardCell` (+`MVCardContent`), `MVFileCardCell`, `MVStatusChipsView`, `MVSectionHeader`, `MVEmptyStateView`, `MVFloatingAddButton`, `MVTypeFilterSheet`, `MVDetailsSheet`, `MVDownloadActions`, `MVDownloadRow`. The OLD `MVTaskCell`/`MVDownloadCell` are GONE — `MVTaskCardCell` now renders every download row, so the old "two cell classes / never cast" crash trap no longer applies. Layout tokens + fonts live in `MVTheme` (`cardCornerRadius`/`cardSpacing`/`screenPadding`/`minTouchTarget`, `cardTitleFont`/`cardDetailFont`/`sectionHeaderFont`/`chipFont`, `applyIconTileStyle:tint:`). Cards are plain UIViews with `+[MVTheme applyCardStyle:cornerRadius:]`, not a wrapper class.
- Files tab (2026-11-11): a kind bar (All/Video/Audio/Other) sits above the list. Video/Audio/Other walk the WHOLE tree by extension (`pathsMatchingKind:underPath:`) so a download is found in any folder; All browses folders. `visibleEntries` returns absolute paths (not names) and is memoised against the kind|filter|folder key — without the cache a kind filter re-walks the tree once per row. Sort/new-folder buttons are disabled outside All. "Show in Files" on a finished download posts `MVRevealFileNotification` → `MVTabBarController` switches to tab 2, pops to root, calls `revealPath:` (pushes the containing folder when needed, falls back to All if the kind filter hides it, scrolls, then flashes the cell via `MVFileCardCell.flashHighlight`).
- `scripts/check-strings.py` verifies every `[MVLang t:@"…"]` literal exists in the table and reports duplicates; run it after touching UI strings (it fails the gate otherwise).
- Build trap: using `UTType*` (UniformTypeIdentifiers) compiles but fails at LINK with `_UTTypePlainText` undefined — those globals are weak-linked, so `scripts/build.sh` must pass `-framework UniformTypeIdentifiers`. Same shape applies to any new framework.
- ObjC traps that broke CI in the redesign: `nullable` is NOT usable inside an `NS_ASSUME_NONNULL` block (use `_Nullable`); a bare message-send inside an `@[...]` literal does not parse (assign to a local first); a `copy` block property must be nil'd in `-prepareForReuse`, and declaring explicit setters for it in the .m is the clean way.
- ObjC API traps hit in CI: `WKWebView findString:withConfiguration:completionHandler:` (NOT `configuration:`); `stringByRemovingPercentEncoding` (NOT `.removingPercentEncoding` property); `WKContentRuleList` has no `.rules`.
- Auto Layout trap: a scroll view's content pinned to its FRAME anchors can never scroll (content width == visible width) and fights fixed-width children. Pin to `scroll.contentLayoutGuide` and take the height from `frameLayoutGuide`. Also set a horizontal stack's `alignment` (default Fill stretches a fixed-height tile).
- Ad blocker (`MVAdBlocker`): WebKit rejects the WHOLE content-rule list if one rule is invalid (`WKErrorDomain error 6`). Two traps: (1) `if-domain` maps to `IfTopURL` — the **page** URL, not the request — so an ad-host `if-domain` list never blocks requests *to* those hosts; use a `url-filter` matching the request host instead. (2) when a list is refused, `probeRules:` recompiles each rule alone and keeps the accepted ones (`MoodyVidAdsGood`), so one bad rule no longer disables everything. If ads appear, grep the log for `adblock:`. Rules are built at runtime via `NSJSONSerialization` in `MVAdBlockRules()` (an array of single-rule JSON strings), not a hand-escaped literal.
- Side-by-side builds: `scripts/build.sh` reads app identity from env (MV_APP_NAME / MV_BUNDLE_ID / MV_DISPLAY_NAME / MV_ICON_TOP / MV_ICON_BOTTOM) with shipping defaults. Two apps only coexist if their CFBundleIdentifier differs; same id = install replaces. The workflow has a `variant` workflow_dispatch input that builds `com.mody.moodyvid.test` / "MoodyVid Test" / purple icon. `make_icon.py` takes optional r,g,b top/bottom colours.
- Build script `scripts/build.sh` fetches yt-dlp nightly by explicit tag then stable, with a `fetch()` retry helper (upstream 504s made builds red).
- ObjC trap: ANY property whose name starts with `init` (initSegment, initTemplate, initStart…) makes clang read its getter as an init method → rename (mapSegment/mapTemplate/mapStart).
- See daily logs: 2026-11-06.md, 2026-11-09.md, 2026-11-10.md, 2026-11-11.md.
- Pause/resume (yt-dlp engine, 2026-11-11): a pause can't suspend yt-dlp, so it unwinds like a cancel but keeps the `.part` file. `MVPython` gains `pausedTasks` + `mvnative.paused(task)`; `MVDownloadEngine` gains `pauseDownload:`/`resumeDownload:` and treats `"paused"` as an error code that sets `MVDownloadStatePaused` (keeps fragments) instead of Failed. Two traps: (a) a paused merged (1080p+) job must KEEP its `.video` fragment — resuming reuses `existingFragmentFor:marker:` so only the audio is re-fetched; (b) `finishJob:` now bails when `_running[id]` is a *different* job, because a resume can queue a replacement before the paused callback lands (the late callback would otherwise clobber it). `MVDownloadRecord.isActive`/`MVDownloadTask.isActive` include the Paused state.

- yt-dlp page downloads need the LIVE page URL. `tab.url` only updates on `didFinishNavigation`, so a SPA (YouTube) leaves it stale; the sniffer script now reports `location` changes and the download reads `webView.URL`. See `.openhands/memory/2026-11-10.md`.
- YouTube player clients: `android` works (combined mp4); web styles (tv_simply/web_safari/mweb/web_embedded) are bot-blocked. Datacenter IPs are blocked, so device testing matters.
- High quality (>=1080p and "best") = two fragments + native mux, because iOS has no ffmpeg. Fragments are named `.video.`/`.audio.`; the mux/MP3 target MUST differ from its source (`derivedPathFor:` strips the marker and adds `-merged`/`-mp3`) — the old code muxed onto the video file itself and produced an empty result. `+[MVMediaConverter hasAudioTrack:]` skips the audio download when the picture already carries sound. Fragments are tracked in `_fragments` and cleaned on success/failure/cancel. See `.openhands/memory/2026-11-10.md`.
