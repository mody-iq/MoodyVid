## Key design decisions
- One Downloads list for two engines: `MVDownloadRow` wraps `MVDownloadRecord`
  (yt-dlp) and `MVDownloadTask` (manager). The table switches on `row.kind`.
- Un-built engines (HLS, torrent) create an *honest failed row* with a localized
  reason, not a row stuck at 0%. `MVDownloadManager resumeTask:` keeps that true.
- Sniffer probes only genuinely new URLs (store `addItem:` returns BOOL).
- Clipboard banner only *offers*; the pasteboard is read on tap (iOS 16+ prompt).

# 2026-11-09 — stage 2: segmented + HLS engines

All merged to main; each change built green on CI before moving on.

## Build resilience
`scripts/build.sh` no longer depends on one CDN for yt-dlp: it reads the newest
tag from `yt-dlp/yt-dlp-nightly-builds` (that repo publishes only pre-releases,
so `--latest` skips it), falls back to the stable repo, then to a plain URL, all
through a `fetch()` helper that retries 5× with backoff and rejects an empty
body. It also asserts the downloaded file starts with a shebang, so a truncated
file fails at build time, not at on-device import. LAME goes through `fetch()`
too. (Root cause of the red main build: `curl: (56) … 504` on the nightly.)

## MVFastDownloader — multi-connection
- Probe first (`Range: bytes=0-`): a 206 gives the total in `Content-Range` and
  proves Range; a 200 means one plain stream.
- Split into `min(connections, 16)` segments, each ≥512 KB, file ≥2 MB. Each
  segment = own NSURLSession + own `.partN` file + own byte range + own retries.
- Plan persisted on the task; a relaunch with the same plan resumes each piece.
  A different plan wipes the parts (`removePartFilesForTask:`).
- Server that answers a ranged segment with 200 → `collapseToSingleConnection:`
  (sets `forceSingle` so it never loops back through the probe).
- Join streams the pieces through a 1 MB buffer off the main thread.
- Delegate callbacks resolve the transfer via `taskDescription` ("id#index"),
  O(1), not a scan per data chunk.

## MVHLSDownloader — native HLS
- master playlist → first variant; media playlist requires `#EXT-X-ENDLIST`.
- Handles `#EXT-X-BYTERANGE` (with the carry-over-offset form), `#EXT-X-KEY`
  (AES-128 CBC, IV from tag or media sequence), `#EXT-X-MAP` (fMP4 init).
- 4 segments in flight; join off-main; MPEG-TS → MP4 remux with AVFoundation
  (passthrough, no re-encode); fMP4 is renamed. A failed remux keeps the `.ts`.
- Live / SAMPLE-AES / DASH fail with a clear localized reason.
- `MVDownloadManager` routes HLS for start/pause/cancel/delete + concurrency.
